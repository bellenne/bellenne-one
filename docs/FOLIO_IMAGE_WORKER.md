# Folio ↔ FolioImageWorker

Folio хранит очередь заданий. Узел опубликованного сценария создаёт задание
после получения фотографии покупателя. В текущем сценарном потоке Folio
отправляет ровно одно сохранённое фото, инструкцию шага и размер в сантиметрах.
Если в брифе несколько фото, Folio не выбирает одно автоматически: фиксирует
ошибку сценария и передаёт чат менеджеру. Это ограничение сценария, а не API
воркера (контракт воркера допускает несколько входных изображений).
Worker работает на обычном ПК по HTTP. Folio получает его уведомление о
готовности и может повторно проверить статус задания.

Размер считывается из суффикса артикула продавца: например,
`КАРТЕСТ-01_40х60` означает ширину 40 см и высоту 60 см. Если суффикса нет,
для старых артикулов применяется 40×60 см. Некорректный суффикс размера
считается ошибкой, а не заменяется молча значением по умолчанию.

Folio передаёт воркеру не более одного задания одновременно. Следующее
выдаётся после подтверждённого завершения или ошибки предыдущего. В API v1
воркера нет метода проверки свободного слота, поэтому Folio определяет
освобождение по статусу задания. При неопределённом результате передачи
очередь останавливается: повторная отправка без проверки могла бы создать
дубликат.

## Настройка

1. Укажите `FOLIO_PUBLIC_BASE_URL=https://<публичный-домен-BellenneOne>` в
   `.env` BellenneOne. По этому адресу Nano Banana скачивает фото и отправляет
   callback. Домен должен быть доступен из интернета по HTTPS.
2. В `.env` worker укажите тот же `FOLIO_PUBLIC_BASE_URL`, один
   `WORKER_API_KEY`, настройки Nano Banana и UNC путь папки печати. Права на
   эту папку нужны Windows агенту, который копирует готовый TIFF; Docker к
   сетевой папке не подключается. См. комментарии в
   `BellenneFolioImageWorker/.env.example`.
3. В Folio откройте **Настройки → Воркер изображений**. Введите адрес ПК
   `http://<IP-компьютера>:8000` и тот же ключ. Нажмите «Проверить доступ».
   Контейнер Folio должен иметь сетевой доступ к этому адресу.

Другие адреса и токены вводить не нужно. Folio сам создаёт ссылку на фото;
worker сам вычисляет callback Nano Banana, разрешённый домен и подпись своего
webhook. Ключ не передаётся в браузер и не попадает в публичную ссылку.
Маршруты `/folio/image-worker/input/...`, `/folio/image-worker/webhook` и
`/folio/image-worker/vendor-callback/...` должны проходить через gateway без
авторизации по сессии: доступ к фото ограничен случайным токеном, а webhook
проверяет подпись. Остальные страницы Folio требуют входа.

Пока нет ключа Nano Banana, оставьте `NANOBANANA_MODE=mock` для проверки цепочки.
Этот режим не редактирует изображение. После покупки ключа переключите на
`live` и задайте `NANOBANANA_API_KEY`.

Узел сценария «Создать макет через воркер» автоматически ставит задание в
очередь. Укажите инструкцию обработки и переход на случай ошибки. Следующий
шаг выполняется только после успешного результата воркера; при ошибке
выполняется заданная ветка. Страница «Задания на макеты» показывает очередь
и результаты.

Сценарий можно скачать на странице «Сценарии» как черновик или опубликованную
версию. На другом сервере загрузите JSON через «Импорт сценария». Импорт
создаёт **новый неопубликованный черновик**: проверьте схему, опубликуйте её
и привяжите к нужным артикулам в разделе «Товары». Настройки интеграций,
секреты, привязки артикулов, чаты и активные диалоги в файл не включены.
