# BellenneFolio — Ozon Seller API feasibility

Проверено: 22.09.2026.

Дополнительная проверка на локальном кабинете 24.09.2026: `/v3/chat/list` возвращает тип и ID чата, но не имя покупателя и не номер заказа. В `/v3/chat/history` пользователь содержит `id` и `type`; `context.order_number` и `context.sku` присутствуют лишь у части сообщений. Метод `/v4/posting/fbs/list` подтверждён с `sort_dir`, `cursor` и точным фильтром `order_numbers`; из найденного отправления можно получить отдельные `posting_number` и `order_number`. `customer` и `addressee` у части отправлений равны `null`, поэтому имя покупателя нельзя гарантированно получить автоматически. Folio не угадывает связь по времени, SKU или тексту переписки: обрабатывает только чат, созданный собственной задачей `start_chat` для конкретного отправления с привязанным `offer_id`. Старые и внешние чаты остаются в БД, но не показываются в рабочем Inbox.

Проверка реального диалога 25.09.2026: Ozon сохранил исходящее сообщение и ответ покупателя, хотя Folio пометил отправку `unknown` из-за неверного разбора ответа `send/message`. История вернула тот же текст с двумя пробелами перед переносами строк. Теперь Folio принимает строковый ID из ответа, а при сетевой неопределённости сам сопоставляет единственное сообщение продавца по ID чата, нормализованному тексту и времени, затем продолжает обработку ответа. Неоднозначные совпадения не превращаются в подтверждение и не вызывают повторную отправку.

Изменение обычного статуса или количества позиции при синхронизации не переводит диалог в ручной режим. Если Ozon сообщает `cancelled`, Folio закрывает экземпляр сценария, отменяет ещё не отправленные сообщения бота и сохраняет последующие сообщения покупателя без автоответа и без автоматической передачи менеджеру. Возобновить сценарий для отменённого заказа нельзя.
Старые неопределённые попытки создания чата для отменённого отправления Folio автоматически закрывает без повторного вызова `/v1/chat/start`; они остаются в административном журнале как история и не показываются в списке заказов как требующие сверки.

Автозапуск: синхронизация FBS-заказов сохраняет позиции; для нового отправления с ровно одной позицией, чей артикул продавца привязан к опубликованному сценарию, создаётся единственная долговечная задача начала чата. Ручного списка статусов Ozon нет. Начало заказа берётся из `in_process_at` в ответе `/v4/posting/fbs/list`; на локальном кабинете это поле присутствовало во всех 100 проверенных отправлениях. Автозапуск допускается только для заказов, созданных после явного включения автоматизации. Если дата отсутствует, отправление отменено или в нём несколько настроенных позиций, чат не начинается: `/v1/chat/start` привязан к отправлению, а Folio не должен смешивать брифы. Отдельные права на создание, отправку текста и получение вложений не могут быть подтверждены безопасным read-only запросом. Их неизвестное состояние показывается в UI, явное включение автоматизации запускает первое реальное действие; подтверждённый отказ блокирует следующий автозапуск. Реальной отправки покупателю при локальной проверке этого изменения не выполнялось.

Проверка каталога на том же локальном кабинете 24.09.2026: `POST /v3/product/list` с `filter.visibility=ALL`, `limit` и `last_id` доступен для чтения. Ответ содержит `offer_id` (артикул продавца), отдельный числовой `sku` Ozon и `product_id`. Выбор на странице «Товары и шаблоны» и сопоставление заказов используют `offer_id`; числовой `sku` не является артикулом продавца.

Этот документ фиксирует только подтверждённый публичный контракт. Доступность каждого метода для конкретного кабинета устанавливается кнопкой «Проверить доступ» и фактической работой тестового чата. Валидный API-ключ не означает наличие прав на чаты или вложения.

## Матрица методов

| Требование Folio | Подтверждённый метод | Состояние реализации | Ограничение |
|---|---|---|---|
| Проверка кабинета | `POST /v1/seller/info` | `OzonAdapter.seller_info` | Проверяет ключ и кабинет, но не права чатов |
| FBS-заказы | `POST /v4/posting/fbs/list` | постраничный импорт с checkpoint | `/v3/posting/fbs/list` отключён 31.08.2026 |
| Каталог товаров | `POST /v3/product/list` | фоновое обновление и выбор по `offer_id` | Доступ проверен на локальном кабинете; при ошибке прежний полный снимок каталога сохраняется |
| Список чатов | `POST /v3/chat/list` | cursor pagination | `/v2/chat/list` удалён из документации |
| История чата | `POST /v3/chat/history` | постраничное чтение и dedup по `message_id` | Реальный доступ зависит от кабинета |
| Текст покупателю | `POST /v1/chat/send/message` | outbox, состояния `pending/sent/failed/unknown`, внутренний лимит 1000 символов | Проверяется только явной реальной отправкой в выбранный чат |
| Начать чат | `POST /v1/chat/start` | отдельная write-job без слепого retry | Допустимость для конкретного отправления устанавливается ответом Ozon; Folio не поддерживает ручной список статусов |
| Файл покупателю | `POST /v1/chat/send/file` | отправка JPEG/PNG/WebP через защищённый outbox; при ответе без ID сверка по хешу файла в истории | Метод и поля подтверждены документацией Ozon; право конкретного кабинета проверяется только реальной отправкой, без слепого повтора |
| Входящие вложения | данные `/v3/chat/history` | защищённое скачивание только с доменов Ozon, без redirect, с проверкой DNS и размера | Capability считается подтверждённой после успешного фактического получения |
| Push заказов/чатов | notification API и типы событий Ozon | не активирован; используется polling | Настройка webhook и доступные типы должны быть проверены на кабинете |

## Безопасный режим

Folio не включает автоматизацию, пока не подтверждено чтение кабинета, заказов и списка чатов или пока известен отказ по другим критичным возможностям. История нового чата и отправка первого сообщения проверяются только на реальном подходящем заказе после явного включения. Проверка подключения ничего не отправляет покупателю. Сетевой сбой write-запроса переводит отправку в `unknown`; Folio автоматически сверяет историю, не отправляя сообщение повторно.

## Неподтверждённые решения

- FBO/FBS/rFBS кабинета и фактическая допустимость начала чата Ozon для нового отправления.
- Возможность инициировать чат для нужных заказов.
- Реальный формат фотографий в истории конкретного кабинета и срок жизни URL.
- Разрешение конкретного кабинета на отправку файлов покупателю: read-only проверка его не подтверждает.
- Поддерживаемые push-типы и политика регистрации webhook.

До проверки кабинета эти пункты остаются блокерами только для production-автоматизации, но не для настройки, product mapping, редактора сценариев, dry-run и ручной работы с уже синхронизированными чатами.
