# BellenneFolio — эксплуатация

Folio запускается в общем Compose-проекте двумя процессами:

- `folio` — UI и внутренние HTTP-операции;
- `folio-worker` — синхронизация Ozon, обработка событий и outbox.

Оба процесса используют volume `folio_data`. Отдельный внешний порт не публикуется; интерфейс доступен через `/folio/` общего gateway.

## Первый запуск

1. Укажите `FOLIO_ADMIN_USER_ID` — числовой ID существующего администратора Bellenne.
2. При необходимости задайте `FOLIO_ENCRYPTION_KEY` в формате Fernet. Если переменная пустая, ключ создаётся в `folio_data/credentials.key` с приватными правами.
3. Выполните `docker compose up -d --build folio folio-worker gateway`.
4. Откройте `/folio/settings` и пройдите мастер запуска.
5. Добавьте кабинет Ozon, сохраните ключ и отдельно запустите проверку доступа.
6. Сопоставьте точные `SKU` с опубликованными сценариями. Тип товара берётся из выбранного сценария.
7. Проверьте каждый сценарий на canvas и выполните dry-run.
8. Подтвердите отправку и вложения на разрешённом тестовом чате. Только после этого включайте автоматизацию.

Проверка подключения является отдельной диагностической операцией: она читает сведения о кабинете, минимальную страницу заказов и доступные страницы чатов, но ничего не отправляет покупателям и не импортирует рабочие данные. Права отправки и получения вложений подтверждаются только фактической безопасной проверкой в разрешённом чате — Folio не имитирует эти возможности по одному успешному запросу.

## Обновление с раннего прототипа

Параметры `http_timeout`, `request_interval`, `media_mimes`, `message_max_chars`, `media_max_bytes` и `media_hosts` удалены из пользовательских настроек. Это транспортные детали, а не настройки продукта. Лимит текста Ozon (1000 символов), безопасный предел изображения и допустимые домены Ozon применяются внутри приложения. При первом запуске новой версии старые поля удаляются из SQLite автоматически, а внешняя запись приостанавливается до повторной проверки возможностей кабинета. Не переносите эти поля в новый `.env` или через UI.

Старая таблица привязок по `offer_id` автоматически заменяется привязками по `SKU`. Если у старой привязки был ровно один уже импортированный SKU, связь сохраняется. Неоднозначные старые записи не переносятся: их нужно один раз сопоставить в UI, чтобы Folio не выбрал сценарий по догадке.

Если в журнале осталась старая операция с причиной `configure_http_limits`, интерфейс покажет её как операцию прежней версии. Нажмите «Повторить безопасно» или запустите новую проверку подключения; старые технические поля заполнять не требуется.

## Данные и секреты

- API-ключ Ozon хранится зашифрованным и не возвращается в UI.
- В аудит не записываются API-ключи, тексты переписки, URL фотографий и бинарные данные.
- Медиа доступны только через backend после проверки прав на конкретный чат/позицию.
- `unknown` у исходящего сообщения означает, что отправка могла состояться. Слепой повтор запрещён; результат сверяется через «Журнал».

## Ссылки на фотографии в RetailCRM

Если комментарий узла «Создать сделку в RetailCRM» содержит `{summary}` или `{photos}`, Folio подставляет ссылки на каждое полученное фото вместо их количества. Для этого задайте `FOLIO_PUBLIC_BASE_URL` — внешний адрес BellenneOne без `/folio`, например `https://one.example.ru`, — и пересоздайте `folio` и `folio-worker`. Для локальной проверки в текущем Compose допустим `http://127.0.0.1:17863`, но такая ссылка открывается только на той же машине и не подходит для рабочего RetailCRM.

Ссылки ведут на `/folio/media/<id>` и требуют авторизации Bellenne и доступа к соответствующему чату. Folio не публикует фотографии без проверки прав и не передаёт в RetailCRM оригинальные URL Ozon или API-ключи. Если внешний адрес не настроен либо файл уже недоступен, создание сделки завершится явной ошибкой до запроса на запись в RetailCRM; бриф нужно проверить в Folio. Уже созданные в RetailCRM сделки автоматически не редактируются.

## Менеджеры Folio и согласование макета

Администратор BellenneOne создаёт логин и пароль менеджера в разделе «Пользователи» Folio. Менеджер входит отдельно через `/folio/login` и видит только доступные ему чаты; учётная запись BellenneOne ему не нужна. На HTTPS-развёртывании задайте `FOLIO_SECURE_COOKIES=true`, чтобы сессионная cookie передавалась только по HTTPS.

В опубликованном сценарии можно разделить первый ответ на текст и фото, затем поставить узлы «Ждать макет менеджера», «Согласование макета» и «Записать итог в RetailCRM». Менеджер отправляет именно файл изображения из чата. Таймер согласования начинается после подтверждённой отправки предупреждения покупателю; при подтверждении, отказе или отсутствии ответа по истечении заданного срока Folio записывает результат в комментарий оператора существующего заказа RetailCRM и передаёт чат менеджеру. Производство автоматически не запускается. Ответ `/v1/chat/send/file` без ID сообщения сверяется с историей Ozon; до сверки файл не отправляется повторно.

Узел согласования использует встроенный версионированный словарь утвердительных и отрицательных ответов. Фразы вручную вводить не нужно. Распознавание точное после нормализации регистра, `ё` и знаков препинания: противоречивые или незнакомые ответы не трактуются как согласие и направляются по ветке ошибки. Черновики переводятся на словарь автоматически; уже идущие диалоги остаются на своей опубликованной версии.

Узел «Записать итог в RetailCRM» теперь может вместе с комментарием изменить статус заказа. Список активных статусов загружается при проверке подключения RetailCRM; API-ключу нужно разрешение `reference_read` наряду с чтением и записью заказов. Пустой выбор не меняет статус. Folio проверяет выбранный код перед записью, сохраняет все товарные позиции в запросе редактирования и не запускает производство самостоятельно.

Для уведомлений настройте входящий webhook в разделе «Mattermost» Folio. Адрес хранится зашифрованным и не показывается повторно. Узел «Сообщение в Mattermost» отправляет заданный текст через фоновую очередь; его можно поставить в ветку ошибки сценария и использовать `{integration_error}`. При заведомом отказе Mattermost выполняется ветка ошибки узла. При таймауте или неопределённом результате автоматического повтора нет: проверьте чат Mattermost и журнал Folio, затем разберите чат вручную.

## Проверка

```powershell
Push-Location apps/folio
python -m unittest tests.test_folio -v
Pop-Location
node --check apps/folio/app/static/folio.js
docker compose config --quiet
docker compose build folio
```

Реальные права и ограничения Ozon проверяются только на конкретном кабинете. См. `docs/FOLIO_OZON_FEASIBILITY.md`.
