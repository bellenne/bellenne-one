# Folio → MES: данные позиции заказа

Обновлено: 20.10.2026. JSON version: 1. Заменяет старый контракт с seller_account_id и скачиванием файла.

## Ответственность

Folio сохраняет печатный макет в примонтированную папку сервера производства.
Только после успешного сохранения отправляет JSON. MES **не скачивает файл и не проверяет его наличие**.
«Принято MES» не означает «напечатано»: MES самостоятельно подготавливает производство через Horizon default. Folio не управляет очередями MES.

Блок «Передать заказ вебхуком» подключается к нужной ветке сценария, например «Согласовано».
Симулятор не сохраняет файл и не отправляет запрос. Опубликованные графы не мигрируют.

## Настройки

«Настройки → Вебхук заказов», только admin:
1. HTTPS-адрес MES: домен либо полный /api/v1/folio/orders.
2. Bearer-токен MES «API Ключи» → folio.send_token. Хранится зашифрованно; не возвращается в UI. Пустое поле сохраняет старый токен.
3. Положительный ID магазина MES для каждого кабинета Ozon, вручную. Пустое поле запрещает передачу из этого кабинета.
4. Корень печатных файлов в путях воркера, например D:/Print.
5. Папка источников в Core, например /mnt/folio-print (допустимо read-only).
6. Папка сервера производства, например /mnt/production/folio, с правом записи. Должна существовать до отправки.

Пример источника: D:/Print/jobs/abc/print.png → /mnt/folio-print/jobs/abc/print.png.
Выход за пределы корня запрещён. Поддерживаются PNG/JPEG/TIFF/PDF.

Результат сохраняется по схеме **production_root / print_file.id / print_file.filename**.
UUID-каталог предотвращает столкновение одинаковых имён. Используются временный файл, flush/fsync и атомарное переименование.
Старый /folio/integration-files/ отключён (410). Публичного URL и токена скачивания больше нет.
Старые приватные копии автоматически не удаляются; срок хранения не задан.

Папки должны быть доступны фоновому процессу Folio Core. Хранилище FOLIO_DATA с БД должно переживать пересоздание контейнера.
Администратор отвечает за монтирование: Folio не отличает сетевой том от локальной папки с тем же путём.

## Запрос

POST https://<домен-MES>/api/v1/folio/orders

```http
Authorization: Bearer <folio.send_token>
Content-Type: application/json
Accept: application/json
Idempotency-Key: 59de1475-7358-43cd-aa2f-1a4ea4ef901a
```

```json
{
  "version": 1,
  "order": {
    "source": "ozon",
    "shop_id": 12,
    "order_number": "12345678-0001",
    "posting_number": "12345678-0001-1",
    "item_id": "folio-item-123",
    "offer_id": "ART-40x60",
    "width_cm": 40,
    "height_cm": 60,
    "quantity": 2
  },
  "print_file": {
    "id": "59de1475-7358-43cd-aa2f-1a4ea4ef901a",
    "filename": "ART-40x60-print.png"
  }
}
```

Все поля обязательны; 12 — пример, не значение по умолчанию.
- shop_id передаётся напрямую; сопоставления кабинетов на стороне MES нет.
- order_number — номер заказа Ozon; posting_number — номер **отправления**, не поставки FBO. Исходные строки и ведущие нули сохраняются.
- item_id — стабильный ID позиции Folio, не артикул; offer_id — артикул продавца.
- Размеры — положительные конечные числа в сантиметрах из задания, без зеркальных/белых полей. quantity — положительное целое.
- Строки — 1–255 символов, JSON UTF-8 — до 64 KiB.
- print_file.id — UUID, в этой реализации совпадает с UUID события. filename — фактическое имя сохранённого файла.
- Не передаются order.type, order.seller_account_id, URL, бинарный файл, переписка, данные покупателя, результат или время согласования.

Выбирается печатный результат **последнего действительно отправленного превью по позиции**, не просто последняя генерация.
Сторонний файл менеджера без связанного печатного результата — ошибка, без подстановки случайного макета.

## Событие и дубли

UUID сохраняется при постановке в очередь. После сохранения файла Folio фиксирует неизменяемые JSON и адрес назначения в БД, затем выполняет POST.
Одна позиция — одно событие. Несколько позиций отправления имеют одинаковые shop_id/posting_number, разные item_id и UUID.
Одинаковые номера в разных магазинах не объединяются.

Повтор, включая ручной повтор и восстановление после перезапуска, использует **тот же UUID и тот же JSON**, включая ID файла.
Настройки магазина и данные позиции не пересобираются для уже подготовленного события.
Другой блок вебхука для той же позиции использует существующее событие. Новый UUID для обхода принятия/конфликта не создаётся.
Изменение принятой позиции требует ручной сверки с MES.

MES атомарно дедуплицирует по Idempotency-Key. Потеря ответа не означает, что запрос не принят.
Смена URL не перенаправляет подготовленное событие на другой сервер.

## Ответы

Успех: только HTTP 200/202, JSON-объект с accepted: true и непустым строковым external_order_id (до 255 символов). duplicate: true тоже успех.

```json
{"accepted": true, "duplicate": false, "external_order_id": "12345"}
```

| Ответ | Действие Folio |
|---|---|
| 200/202 + корректное подтверждение | Принято MES; сохранить ID |
| 200/202 + HTML/неверный JSON/нет подтверждения | Повтор с тем же событием, не успех |
| 400/422 | Ошибка данных, без автоматических повторов |
| 401 | Приостановить всё подключение до исправления токена |
| 409 | Ошибка, ручная сверка; не менять UUID |
| 503 CONFIGURATION_ERROR | Приостановить подключение до исправления MES |
| Сеть, таймаут, прочие 5xx, 408/429 | Повтор с задержкой |
| Прочие коды, включая redirect | Ошибка без автоматического повтора |

Паузы: **1, 2, 5, 15, 30 минут, затем каждый час**, без максимального числа попыток.
Числовой Retry-After может увеличить задержку. HTTP timeout — 15 секунд на операцию I/O; редиректы запрещены.
После аварии незавершённая попытка восстанавливается по истечении пятиминутной блокировки.

Поддерживаются ошибки MES в message, error.message, errors, код CONFIGURATION_ERROR в code или error.code.
Текст ограничивается и токен маскируется; сырой HTML и заголовки не журналируются.

После исправления токена/конфигурации сохраните подключение и повторите ошибочную передачу кнопкой.
409 требует отметки о ручной сверке. Повтор не обнуляет счётчик, не запускает генерацию и не откатывает ветку ошибки сценария.
Если JSON уже подготовлен, изменить его кнопкой повтора нельзя.
Отменённые заказы не отправляются. Ручной режим приостанавливает автоматическую передачу; отдельный администраторский повтор возможен без перезапуска сценария.

## Интерфейс и переход

Состояния: «Ожидает», «Принято MES», «Повтор запланирован», «Ошибка».
Хранятся попытки, время последней/следующей попытки, HTTP-код, причина, ID заказа MES.

Старые события сохраняются без изменения JSON. Незавершённые старые события при обновлении блокируются.
Старые принятые события не переотправляются; кнопка повтора старого контракта недоступна.
Массовая миграция не выполняется, требуется ручная сверка.

Обновить API, фоновый процесс Folio и gateway. Заполнить папку производства, shop_id и адрес MES.
Перепубликовывать сценарий не требуется, если блок уже установлен в нужной ветке.

## Проверки

Локальные тесты с имитацией MES: успех/дубль; несколько позиций; разные магазины с одинаковыми номерами;
таймаут/перезапуск с неизменным событием; график повторов; 401; несуществующий магазин (422); конфликт 409;
503 конфигурации; HTML вместо JSON; ошибка записи файла; старые события; маскировка токена; RBAC; dry-run.
Реальный end-to-end прогон требует развёрнутой MES и подключённой производственной папки.
