# Folio → Laravel: заказ картины, v1

Дата: 16.10.2026. Контракт реализуется модулем Folio; принимающую сторону реализует Laravel.

## Назначение

Администратор ставит блок **«Передать заказ вебхуком»** после ветки «Согласовано».
Сам по себе факт согласования ничего не отправляет: отправка происходит только на этом блоке.
Блок имеет переходы «Следующий шаг» (Laravel принял событие) и «Если вебхук не доставлен».
Отказ/таймаут не должны быть связаны с этим блоком, если передача нужна только при согласии.
Симулятор не отправляет запросов и не копирует печатные файлы.
Публикация новой схемы не изменяет уже начатые диалоги.

## Запрос

`POST <настроенный URL Laravel>`, HTTPS, порт 443, без редиректов.

```http
Authorization: Bearer <send_token>
Content-Type: application/json
Idempotency-Key: 59de1475-7358-43cd-aa2f-1a4ea4ef901a
```

```json
{
  "version": 1,
  "order": {
    "source": "ozon",
    "seller_account_id": "1",
    "order_number": "49778856-0150",
    "posting_number": "49778856-0150-1",
    "item_id": "123",
    "offer_id": "КАРТЕСТ-01_40х60",
    "type": "Картина",
    "width_cm": 40,
    "height_cm": 60,
    "quantity": 1
  },
  "print_file": {
    "id": "59de1475-7358-43cd-aa2f-1a4ea4ef901a",
    "url": "https://one.example.ru/folio/integration-files/59de1475-7358-43cd-aa2f-1a4ea4ef901a",
    "filename": "print.png",
    "mime_type": "image/png",
    "size_bytes": 12345678,
    "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  }
}
```

Пример условный. Все поля обязательны. Идентификаторы и номера — строки; размеры — положительные числа в сантиметрах; quantity — положительное целое.

- order_number — номер заказа Ozon, posting_number — отдельный номер отправления.
- seller_account_id и item_id — стабильные внутренние ID Folio. Позиция сопоставляется по их паре.
- offer_id — артикул продавца, не числовой SKU Ozon.
- type всегда «Картина». Подтип Folio не передаётся.
- Размеры берутся из задания на изображение, без зеркальных полос и белых полей.
- quantity — количество экземпляров одной позиции. Несколько позиций передаются отдельно.
- print_file — печатный файл задания, превью которого последним действительно отправлено в этот диалог по этой позиции. Не выбирается просто самая новая генерация. Если менеджер отправил сторонний файл без соответствующего задания воркера, необходимо привязать печатный результат; отсутствие такого результата — ошибка, а не подстановка произвольного макета.
- Результат/время согласования, данные покупателя, переписка и внутренний путь воркера в JSON не включаются.

## Приём и идемпотентность Laravel

Проверить Bearer-токен и структуру. В транзакции сохранить событие с уникальным Idempotency-Key и поставить обработку в надёжную очередь. Затем ответить, не дожидаясь скачивания файла.

Первое принятие — HTTP 202, повтор ранее принятого события — HTTP 200:

```json
{"accepted": true, "duplicate": false, "external_order_id": "12345"}
```

Для дубля вернуть duplicate=true и прежний external_order_id. Folio проверяет accepted=true; остальные поля предназначены для принимающей стороны.

Один ключ + то же тело не создаёт повторный заказ. Один ключ + другое тело — HTTP 409. Дедупликация должна быть атомарной и выдерживать параллельные запросы.
Новый ID события для той же позиции не должен автоматически создавать дубль: Laravel сопоставляет позицию по seller_account_id + item_id и применяет собственную явную политику обновления.

Ошибки: 400/422 — формат; 401/403 — авторизация; 409 — конфликт ключа; 429 — перегрузка; 5xx — временный сбой.

```json
{"accepted": false, "error": {"code": "VALIDATION_ERROR", "message": "Не указан номер отправления"}}
```

Folio не отображает и не журналирует произвольное тело ответа. В интерфейсе сохраняется HTTP-код/безопасная причина.

## Повторы Folio

- Снимок JSON и файла сохраняется до POST; повтор использует тот же ключ и тело.
- Таймаут HTTP-клиента — 15 секунд на операцию ввода-вывода.
- Сеть/408/429/5xx: до 5 попыток, базовые паузы 60/120/240/480 секунд. Числовой Retry-After может увеличить паузу.
- Остальные HTTP-коды, некорректное подтверждение, отсутствие настройки/файла — ошибка блока.
- После перезапуска незавершённая доставка повторяется с прежним ID по истечении 5-минутной блокировки обработки.
- Администратор может повторить ошибочную доставку в настройках с тем же ID. Это повтор доставки, не повтор сценария/генерации. Уже выполненная ветка ошибки не откатывается.
- Отменённые заказы не отправляются. Автоматическая отправка приостанавливается в ручном режиме; явно запрошенный администратором повтор доставки разрешён без возврата сценария.

Laravel обязан реализовать дедупликацию ДО подключения: потеря ответа не означает, что событие не принято.

## Скачивание файла

```http
GET <print_file.url>
Authorization: Bearer <download_token>
```

download_token отличается от send_token. Он передаётся разработчику вне JSON вебхука и хранится на сервере Laravel.
Ответ 200 — бинарный файл с Content-Type и Content-Disposition. 401 — неверный токен, 404 — нет файла. Вход через браузер/сессию Bellenne не требуется.

Laravel скачивает в своей очереди, проверяет size_bytes и SHA-256, сохраняет свою копию, затем отмечает готовность заказа. Ошибки скачивания повторяет отдельно от создания заказа. Не загружать весь файл в память.
Разрешить загрузки только с настроенного домена Folio. Не передавать Authorization на другой домен и не следовать произвольным редиректам.

Folio создаёт приватную копию печатного файла до отправки события; ссылка фиксирует эти байты. Изменение исходного файла/монтирования после отправки не изменяет содержимое ссылки. Автоматическое удаление/срок хранения пока не заданы. Требуется учитывать место на диске.

## Настройки и развёртывание Folio

Раздел «Настройки → Вебхук заказов», только admin:

1. URL обработчика Laravel.
2. Публичный URL Folio с префиксом, например https://one.example.ru/folio.
3. Токен отправки в Laravel, минимум 32 символа без пробелов.
4. Отдельный токен скачивания из Folio, минимум 32 символа.
5. Корень печатных файлов в путях, возвращаемых воркером, например D:/Print.
6. Папка монтирования внутри Core, например /mnt/folio-print.

Пример сопоставления: D:/Print/jobs/abc/print.png → /mnt/folio-print/jobs/abc/print.png. Сохраняется относительный путь; нельзя подставлять только имя файла. Обратные слеши Windows поддерживаются. Выход через `..` или symlink за пределы mount_root запрещён. Допустимы PNG/JPEG/TIFF/PDF.

Папку результатов монтировать read-only в процесс/контейнер фонового worker Folio. Хранилище FOLIO_DATA с приватными копиями должно быть общим и постоянным для API и worker. При запуске API/worker в одном контейнере достаточно одного монтирования. Папка worker_root является префиксом сопоставления, не папкой на сервере Core.

Обновить Folio API, фоновый worker и конфигурацию gateway/nginx.conf: путь /folio/integration-files/ использует Bearer-авторизацию самого Folio вместо браузерной авторизации Shell. Остальные пути остаются защищены как прежде.

Настройки зашифрованы для секретов; сохранённые токены обратно в UI не выводятся. Пустое поле оставляет токен прежним. Смена download_token требует обновления Laravel. Смена URL во время повтора не перенаправляет ранее подготовленное событие на другой сервер.

## Приёмка Laravel

Проверить: правильный/неправильный токен; повтор и конкурентный повтор; конфликт тела; две позиции одного отправления; несколько заказов одного покупателя; потерю HTTP-ответа; скачивание без cookies; неверный токен файла; повтор скачивания; несовпадение размера/хеша.

Получение события не является командой автоматического запуска производства. Действия после сохранения данных определяются Laravel отдельно.
