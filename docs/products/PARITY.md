# BellenneParity

Parity — модуль контроля цен собственных кабинетов Wildberries и Ozon.
Требования пользователя сохранены в `docs/TZ_PARITY.md`.

Основные страницы: Обзор, Товары, Расхождения, Сопоставления, Интеграции,
Журнал, карточка товара с графиком и точной историей. Модуль читает каталог через API и цены с динамических покупательских страниц; изменение цен, рекомендации и сторонние уведомления отсутствуют.

UI использует `docs/BRANDBOOK.md`, Shell, общие CSS-компоненты и SVG-паттерн
графиков Bellenne. Новый Product Accent не утверждён: применяется существующий
платформенный `--bp-violet`; новая палитра не вводится. Pulse не изменяется.

Marketplace SKU, product ID и артикул продавца — отдельные поля.
Автоматическое сопоставление возможно только при единственном точном совпадении
артикула на каждой площадке. Ручное создание/исправление связи и отвязка доступны
из UI. Отвязка фиксирует ручное решение и не отменяется следующей синхронизацией.

Текущий источник цен — витрина текущего профиля браузера покупателя, WB Кошелёк и Ozon Карта. Проверок входа и Москвы в расширении нет; отдельная серверная гостевая диагностика использует Москву. Основной ручной запуск использует расширение Chrome/Edge; серверная гостевая проверка остаётся отдельной диагностикой. Подключение и очередь описаны в `docs/PARITY_EXTENSION.md`. Сравнивается только подтверждённая цена выбранного способа оплаты. Обычная и зачёркнутая цены сохраняются справочно. История Seller API отделена; семантика старых данных описана в `docs/PARITY_API.md`. Новый сбор описан в `docs/PARITY_STOREFRONT.md`.
Сравнение относится к подтверждённым ценам витрины в зафиксированном контексте
браузера и не обещает одинаковых персональных цен всем покупателям. Недоступная цена — null, а не ноль.

Каждый пользователь BellenneOne управляет своим кабинетом Parity, включая
административные страницы интеграций и сопоставлений. Все методы backend
изолируют данные по доверенному ID из gateway; совместный доступ сотрудников
к одному кабинету не реализован и не включается автоматически.

Внешние API вызываются отдельным worker. UI ставит задачу в долговечную очередь
и получает ID. Процент прогресса не придумывается. Ежедневное время и часовой
пояс задаются в UI; расписание по умолчанию выключено до настройки. Ежедневная
фиксация неизменившейся цены сохраняется. Витрина фиксируется на каждом успешном
задании; повторная передача одной карточки того же задания не создаёт дубль.

При полном отказе API одной площадки её текущие цены и признаки наличия товара
не меняются. Успешная площадка обновляется, итог задания — partial. Отсутствие
товара устанавливается только после полной успешной загрузки каталога.
После неудачной синхронизации сравнение — stale, до следующей успешной загрузки.
Порог устаревания настраивается в UI; первоначально 24 часа, исходя из ежедневного
обновления. Порог денежного расхождения первого этапа равен нулю.

Ключи шифруются Fernet, никогда не возвращаются frontend и не попадают в журнал.
Ошибки содержат безопасный код, площадку и ID задания, без внешних response bodies.


Ошибки отдельной карточки браузерного сбора не останавливают очередь: товар
автоматически пропускается, причина и счётчик сохранены, сбор идёт дальше.
«Нет в наличии» не создаёт нулевую цену и не удаляет товар из Seller API каталога.
Остановка/пауза — только команды пользователя; прошлые снимки сохраняются.
