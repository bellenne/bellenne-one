# Витринный сбор Parity

Актуальное требование: Москва, цена с WB Кошельком / Ozon Картой.
API продавца предоставляет только каталог. Его цены не подставляются при
ошибке браузерного сбора. Старые снимки остаются в «История Seller API».

Основной ручной сбор теперь выполняется расширением: `docs/PARITY_EXTENSION.md`. Ниже описана серверная гостевая реализация и её исторические проверки.

## Серверный механизм

`parity-worker` содержит Playwright 1.63.0 и Chromium с системными библиотеками.
Новая зависимость нужна для загрузки JavaScript и чтения видимого DOM;
UI-зависимости не добавляются. API-контейнер не содержит браузерных бинарников.
Один браузер на задание, отдельная гостевая сессия каждой площадки, последовательный
просмотр карточек. Cookies действуют только внутри задания. Личные профили,
пароли покупателей и токены Seller API в браузер не передаются.

На каждую карточку проверяются покупательский идентификатор, явно отображаемая
Москва, валюта и основной блок цены. WB использует отдельный Wallet price,
Ozon — явно подписанную Ozon Card либо «С банками» с явным логотипом Ozon Card.
Минимальная сумма на странице, рассрочка, рекомендации, вычисленный процент
скидки и обычная цена не используются вместо выбранной цены.
URL Ozon строится по SKU, не по seller product_id.

Пауза между началами просмотров — 2 секунды по умолчанию, регулируется в UI
от 2 до 60 секунд. Это ограничение нагрузки, а не обещание скорости.
Таймауты загрузки и ожидания DOM используют существующий
`PARITY_HTTP_TIMEOUT_SECONDS` (30 секунд). Heartbeat обновляется в ходе ожидания.
При блокировке или ошибке загрузки страницы следующие карточки площадки пропускаются; другая площадка
обрабатывается отдельно. CAPTCHA не решается, защита не обходится.

Успешная карточка публикуется отдельной транзакцией: снимок, текущий указатель,
условия, статус попытки. Ошибка сохраняет последний снимок, но запрещает его
актуальное сравнение. Незавершённый запуск после истечения lease получает
`interrupted`. Полученные до прерывания снимки сохраняются.

Источник и версия условий фиксируются в снимке. История / изменение цен не
соединяют Seller API с витриной и разные версии условий. Сравнивается только
`loyalty_price`; обычная и зачёркнутая цены доступны справочно.
Дополнительно сохраняется JPEG только блока цены, если screenshot доступен.
Файл выдаётся через маршрут, проверяющий владельца; cookies, переписка и полный
экран покупателя не сохраняются. Автоматический срок удаления не назначен.

## UI

«Интеграции»: московские условия, интервал, проверка одной карточки площадки,
отдельные ключи и импорт каталогов, ежедневный сбор. Проверки работают без
Seller API ключей при наличии уже импортированного каталога.
В карточке: собрать один товар, открыть покупательскую ссылку, источник / время /
условия, причина ошибки, снимок блока цены, выбор текущей или старой истории.
Доступ и CSRF проверяются на backend. Изменения условий во время задания запрещены.

## Миграция и проверки

Migration v2 добавляет поля и таблицу попыток. Каталог, связи и 1117 существующих
API-снимков сохраняются; старое расписание выключается. Перед установкой следует
сделать согласованный SQLite backup через backup API, включая WAL.

Проверка:

```powershell
docker build --target browser-test -t bellenneone-parity-browser-test -f apps/parity/Dockerfile .
docker run --rm bellenneone-parity-browser-test
```

68 тестов: legacy-регрессии, Decimal, селекторы динамического DOM, отсутствие
подмены цены картой другого банка, рекомендации / скрытые / дублированные значения,
ожидание реальной динамической fixture, screenshot, owner isolation / CSRF,
блокировка, частичный сбор, target / probe, история, каталог без замены цен и
миграция. Обычный `test` target может пропустить browser-тесты, если нет Chromium;
для приёмки нужно использовать `browser-test`.

Opt-in live smoke, отдельная временная БД и только две карточки:

```powershell
docker run --rm bellenneone-parity-browser-test python -m tests.live_storefront_smoke
```

На 2026-10-01 карточки WB 701955470 / Ozon 3267204518 открылись в обычном браузере
в Москве, однако **обе площадки заблокировали автоматический просмотр из Docker**.
Live smoke закончился `failed`, без ценовых снимков. Поэтому полноценный ежедневный
серверный сбор пока не прошёл приёмку. На этом этапе пользователь выбрал оставить серверный
сборщик с диагностикой. Позднее одобрено и реализовано расширение (`docs/PARITY_EXTENSION.md`). Локальный браузер с участием пользователя
в авторизации / проверках сайта требует отдельной реализации и проверки;
наличие UI-настроек и проходящих fixture-тестов не снимает это ограничение.

Обновление установлено в работающий Parity после согласованного SQLite backup. Каталог 1117 товаров, 901 связь и 1117 API-снимков сохранены; HTTP 200 подтверждён для первой, второй и последней страниц каталогов, интеграций и обеих историй товара.

После установки также выполнено задание #5 для WB 701955470 в рабочем worker: страница не загрузилась (`navigation`), сохранено 0 новых ценовых снимков. Журнал сохраняет только безопасный код сетевой ошибки, HTTP-статус или timeout, без исходной страницы и заголовков.

Задание #6 в рабочем worker для Ozon SKU 3267204518 подтвердило `blocked`, HTTP 403, 0 новых ценовых снимков. Каталоги, интеграции, обе истории товара и страница задания после финальной установки возвращают HTTP 200.
