# Карта проекта и реализация Parity

До изменений Parity и его продуктовая документация отсутствовали.

| Существующая часть | Решение для Parity |
|---|---|
| Gateway nginx / auth_request | Защищённый `/parity/`, перезапись user/CSRF заголовков |
| Pulse identity/session | Используется без изменений Pulse |
| Shell на FastAPI/Jinja | Ссылка, карточка модуля и ссылка на Integrations |
| Общие theme.css/app.css/app.js | Переиспользуются при Docker build без копий в исходниках |
| SVG icons / charts Bellenne | Тот же набор и паттерн; новая chart library не нужна |
| Отдельные SQLite DB модулей | parity_data, SQLAlchemy, additive baseline migration v1 |
| Worker/DB queue в Folio и Proof | Отдельный Parity worker и собственная durable DB-очередь |
| cryptography/Fernet в интеграциях | Fernet и отдельный key reference в volume/env |
| OzonAdapter Folio | Прочитан существующий контракт; Parity использует изолированный read-only адаптер |

Зависимости Parity совпадают с FastAPI/SQLAlchemy/Jinja/httpx/cryptography стеком
Proof; UI frameworks не добавлялись. tzdata нужен ZoneInfo для configurable IANA
часовых поясов в минимальном Linux image и Windows, где системная IANA БД может
отсутствовать. Clock/scheduler реализован в worker, без новой scheduler library.

Внешние вызовы не выполняются внутри HTTP requests: даже capability probe
ставится в очередь. На владельца допускается только одно активное задание,
поэтому ручной запуск, проверка, расписание и изменения связей/credentials
не конфликтуют. Queue claim и изменения сериализуются SQLite BEGIN IMMEDIATE.
Не следует включать несколько Parity workers на разных хостах с отдельными
копиями volume: для общей очереди требуется одна общая DB.

Нормализованные данные сначала записываются в staging. Только полностью полученный
каталог площадки публикуется транзакционно. Snapshots и current pointer изменяются
вместе. Производительность: пагинация/фильтры/поиск в backend, индексы каталога,
артикула, связей и (product_id, captured_at), ограниченные периоды/таблица истории.
Адаптеры держат индекс названий/цен одной площадки в памяти, но не загружают
историю всех товаров. Для каталогов, не помещающихся в память worker, эти индексы
можно перенести в staging; такой объём нужно измерить на реальных данных.

При смене credentials версия последней успешной загрузки перестаёт совпадать
с текущей версией ключа: старые цены видны, но сравнение stale до нового sync.
Успешная проверка прав сама по себе не обновляет версию данных и историю.

## Проверено

В Docker на Python 3.12 с закреплёнными зависимостями прошли 52 теста.
Собран runtime image с непривилегированным пользователем; `docker compose
config --quiet`, проверка синтаксиса nginx 1.27 и `git diff --check` успешны.

Автотесты запускаются в `apps/parity/tests/test_parity.py`, включая реальные
HTTP-контракты с MockTransport, Decimal, равенство/расхождение/валюты/null,
точные/неоднозначные/ручные связи, исправление/отвязку, изменённый артикул,
partial failure и staging rollback, историю и ежедневную фиксацию, поиск и
пагинацию, owner isolation и CSRF, шифрование/маскировку/validation redaction,
одновременные enqueue/claim, восстановление interrupted, расписание, rate limits.
HTML-пагинация проверена на 121 сопоставленной паре: первая, средняя и последняя
страницы всех трёх каталогов, сохранение фильтров и кодирование специальных
символов; отдельно проверена пагинация журнала с фильтром задания. Эти проверки
воспроизводили и затем подтвердили исправление ошибки QueryParams.remove,
которая проявлялась только после появления нескольких страниц.

После установки исправления в запущенный Parity проверены HTTP 200 на первой,
второй и последней страницах импортированных данных: каталог/связи 19 страниц,
расхождения 5 страниц, журнал 25 страниц. Количество товаров, связей и снимков
при проверке сохранилось. Внешние API и credentials для этой диагностики не нужны.

Отдельно проверено прохождение различающихся `discountedPrice` и
`clubDiscountedPrice` из HTTP-ответа WB через адаптер, staging, snapshots,
все три каталога и данные графика без перестановки и подстановок. Read-only
сверка текущего WB API (769 товаров) с сохранёнными значениями не обнаружила
различий; у 741 товара оба поля имеют одинаковую цену в самом ответе API.
Секреты и исходный ответ при диагностике не выводились.

UI проверяется на отдельном synthetic preview, не на рабочих данных:
сохранение ключа, маскировка, отдельная проверка прав с background job,
поиск, ручные связи, переключение цены/периода, gap графика, мобильный viewport.
На viewport 390×844 подтверждены отсутствие горизонтального выхода страницы,
отдельная прокрутка таблицы и работа меню. Селекты имеют явные label/for;
проверены создание и отвязка manual mapping, точные изменения в истории.

Исторические проверки выше относятся к реализации Seller API. Текущая реализация и ограничения витринного сбора — `docs/PARITY_STOREFRONT.md`.

## Переход на витринные цены (2026-10-01)

Добавлены Chromium / Playwright 1.63.0 в отдельный worker image, DOM-сборщик, московский контекст, проверка Wallet/Card, попытки сбора и снимки блока цены. API больше не является источником цен; каталог импортируется без вызовов price endpoints. Additive migration v2 сохраняет существующие товары, связи и историю и выключает старое расписание. UI позволяет настроить интервал, проверить площадку, запустить весь каталог или одну карточку и отдельно открыть старую историю.

Прошли 68 тестов Python 3.12, включая 4 проверки в реальном Chromium на динамических локальных страницах. Дополнительно выполнен реальный opt-in smoke через очередь приложения для WB 701955470 и Ozon SKU 3267204518: **оба сайта заблокировали автоматический просмотр из Docker**, снимки цен не записаны. Это внешний незакрытый operational blocker; серверный сбор не объявляется работающим на этих сайтах. Нужен отдельно проверенный способ доступа через браузер пользователя; обход защиты не реализован.

## Сводка одинаковых ошибок площадок

Одинаковые сообщения объединяются с указанием площадок (например, Wildberries, Ozon), включая чтение старых заданий в HTML и API; сохранённая история не переписывается. 12 целевых регрессионных тестов прошли. После установки проверено старое задание #8: обе страницы HTTP 200, причина блокировки выводится один раз.

## Расширение браузера (2026-10-01)

Реализованы MV3 пакет Chrome/Edge, same-origin мост авторизованной вкладки,
долговечная очередь BrowserRun/BrowserTask и UI запуска, прогресса, pause/resume,
skip/stop. Повторная передача идемпотентна; worker не забирает задания браузера.
Парсер общий с сервером; профиль браузера и серверная гостевая сессия имеют
разные версии условий. Настройка, ограничения и установка — `PARITY_EXTENSION.md`.

Полный набор из 84 тестов прошёл, затем прошли 15 целевых тестов после оптимизации
пересчёта каталога. Дополнительно добавлена и пройдена проверка responsive UI
390×844, меню и отсутствия горизонтального выхода; расширение проверено на
динамических fixtures, перезапуске persistent Chromium и потере ответа после commit.
Скриншоты тестовой установки находятся в игнорируемом `apps/parity/test-artifacts/`.
Реальные цены в личном браузере требуют установки расширения пользователем и
контрольной проверки WB 701955470 / Ozon 3267204518; live-приёмка не объявлена.

Перед установкой создан согласованный backup
`/data/backups/parity-before-extension-20261001T114845Z.db`. Рабочие API и worker
обновлены, migration v3 выполнена. Сохранены 1117 товаров, 901 связь и 1117 прежних
снимков, active jobs отсутствуют. Интеграции, каталоги/пагинация, старое задание #8
и загрузка ZIP возвращают HTTP 200 во внутренней авторизованной диагностике;
внешний gateway продолжает требовать вход. HTTP-сервис healthy, worker running.

Финальная проверка: полный набор 85 тестов прошёл; после добавления таймаута
зависшей навигации прошли 17 целевых тестов очереди/реального расширения, включая
новый сценарий зависшей страницы без сохранения цены. Финальный пакет установлен
в API/worker и распакован локально для разовой установки пользователем.


## Расширение 1.1: видимый прогресс и восстановление

Окно расширения показывает серверный курсор, число цен/пропусков, артикул, этап,
время последнего результата и безопасную причину остановки. Управление паузой,
продолжением и пропуском проходит через same-origin мост с owner/CSRF/profile
проверками. Последний прогресс сохраняется в chrome.storage.local.

Исправлено повторное попадание в истёкший таймер при продолжении после navigation:
карточка загружается заново. Ответы вкладок ограничены таймаутом, DOM читается
без ожидания зависших второстепенных ресурсов, отсутствующий ответ читателя
переводит сбор в attention. Ограничения сайта по-прежнему требуют действия
пользователя. Исключение — автоматический пропуск identity, описанный ниже.

Проверки: настоящая MV3 сборка в Chromium, повторная загрузка после зависания,
живое обновление popup и итог после его открытия заново, pause/resume/skip,
зависший ответ моста и восстановление, чтение цены при зависшей картинке;
backend проверки владельца/CSRF/привязанного профиля для popup control.


## Расширение 1.2: ограниченный autorеtry

Navigation повторяется в пределах существующего PARITY_RETRY_ATTEMPTS: повторная
загрузка и новая рабочая вкладка, без пропуска карточки и без сброса бюджета при
pause/restart. Номер попытки отображается в popup. Обнаруженные challenge/region/
benefit/setup/layout остаются ручной остановкой. Для identity действует автоматический
пропуск, описанный ниже. Старый ID вкладки после
перезапуска корректно восстанавливается. SAMPLE берёт видимый DOM без зависимости
от таймера фоновой страницы, включая две свежие проверки после его истечения.

Проверки 2026-10-01: полный набор 97 тестов, затем отдельная успешная проверка
финальной ветки SAMPLE после истечения таймера. Это настоящий MV3 в тестовом
Chromium с искусственными страницами; пользовательский Chrome получает изменения
после перезагрузки установленного расширения 1.2 в прежней папке. Очередь #14
с восьмью готовыми снимками сохранена, переходов по ней в ходе разработки нет.


## Продолжение при несовпадении SKU

Обработка identity в браузерной очереди перенесена в автоматический пропуск на
сервере: неверная карточка не создаёт снимок, запись попытки/журнала и skipped
сохраняют причину. Невалидный идентификатор каталога пропускается до открытия.
Уже существующая attention/identity восстанавливается следующим claim своего
профиля; пауза и проверки владельца/профиля/токена сохраняются. Изменений MV3
или миграции БД нет, переустановка расширения не нужна.

Проверки 2026-10-01: 89 тестов backend/витрины/очереди и настоящий MV3 с неверным
SKU Ozon, потерей ответа после commit и последующим успешным WB. Дополнительно
проверены сохранение прежней истории/устаревшее сравнение и сохранение ручной
остановки для navigation/unavailable. В MV3 итог — partial, обработано 2/2,
одна сохранённая цена и один пропуск без ручного продолжения.


Обновлены parity/parity-worker после SQLite backup. Подтверждено на живой очереди
#14: следующий запрос установленного расширения автоматически пропустил identity
(33 сохранённые цены, 1 пропуск, done=34/1117) и перешёл к следующему товару.
На следующей карточке расширение сообщило setup; эта отдельная причина требует
проверки рабочей вкладки пользователем. Живые наблюдения не подменялись, claim или
resume от имени расширения вручную не выполнялись.


## Сбор без требований входа и Москвы (1.2.1)

По прямому требованию пользователя удалены browser setup и проверка города в
расширении/серверном receipt. Прежнее сообщение о входе срабатывало по URL, а не
по фактическому состоянию аккаунта. Читать разрешены только WB/Ozon; переходы
внутри площадки, включая hostname без www, не требуют действия пользователя.
Внешний/нечитаемый переход автоматически пропускается как unavailable. Потеря
content script при редиректе сначала проверяет итоговую вкладку, чтобы не
повторять заведомо нечитаемый адрес как navigation.

В старой установленной версии setup/region автоматически пропускаются как
unavailable; уже остановленная очередь восстанавливается следующим запросом
своего профиля. Пауза пользователя, owner/CSRF/profile и проверка SKU/цены остаются.
Неизвестный город записывается null с region_checked=false, без подстановки Москвы.
Гостевая серверная диагностика сохраняет проверку своего настроенного региона.
Тексты job/integrations/popup больше не требуют входа и выбора Москвы.

ZIP и готовая распакованная папка обновлены до 1.2.1. Для локального кода требуется
перезагрузка расширения в прежней папке; серверное снятие setup/region работает
со старой версией. Проверки: 93 backend/витрина/очередь и настоящие MV3-сценарии
перенаправления на apex Ozon/отсутствия Москвы, внешнего редиректа с пропуском,
неверного SKU/потери ответа, обычного сбора, ручного управления и navigation retry.


После финального исправления и повторных проверок обновлены parity/parity-worker
с резервной копией БД. На реальной очереди #14 установленное расширение само
сняло attention/setup: state=running, 33 сохранённых цены, 2 пропуска, done=35/1117.
API выдаёт пустое требование setup, ZIP endpoint возвращает 1.2.1. Ручной claim,
подмена профиля или выдача фиктивных наблюдений не выполнялись. Дополнительная
проверка мобильного UI/навигации также прошла (итого 7 выбранных MV3-сценариев).


## Все ошибки карточек пропускаются (1.2.2)

По прямому требованию пользователя снята последняя автоматическая остановка
browser queue: любой receipt error и ошибка нормализации ведут к skipped;
старый attention любого кода восстанавливается следующим claim своего профиля.
Сохранены ручные pause/stop, изоляция владельцев/профилей, CSRF, токен, порядок,
идемпотентность, старая история и пересчёт только по завершении задания.
В shared DOM reader добавлено unavailable для явного отсутствия товара без цены.
В MV3 blocked/unavailable считываются по двум стабильным наблюдениям; локальный
сбой назначенной вкладки передаётся как internal. Navigation после ограниченных
повторов также пропускается. Потеря связи сохраняет outbox и автоматически
восстанавливается, без потери результата с неопределённым подтверждением.

Прошли все 114 тестов: 95 backend/витрина/очередь и 19 настоящих MV3 в тестовом
Chromium. Смешанная очередь пяти карточек заканчивается partial (2 цены, 3
пропуска) без ручных действий; проверены таймауты, локальные сбои, перезапуск,
ручная пауза, потеря ответа, SKU, все error codes и старые остановки.
ZIP/готовая папка обновлены до 1.2.2; обновлены parity/parity-worker после backup.
Общий автопропуск работает со старым расширением без обязательного обновления.


Подтверждено после обновления на живом задании #14: прежняя layout-остановка
автоматически пропущена, следующее наблюдение WB сохранено. На момент проверки:
run=running, attention_code=null, done=372/1117, saved=329, skipped=43.
Результаты приходили от установленного расширения; ручные claim/receipt/control
и фиктивные цены для продолжения не использовались. ZIP endpoint отдаёт 1.2.2.
