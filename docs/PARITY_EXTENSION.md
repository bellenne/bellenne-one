# Сбор цен через расширение BellenneParity

Основной ручной запуск в UI теперь использует расширение Chrome/Edge Manifest V3.
Одна кнопка создаёт очередь всех выбранных карточек. Расширение открывает отдельную
рабочую вкладку, последовательно читает динамические страницы и передаёт наблюдения
через открытую вкладку Parity. Проверки WB/Ozon ограничены одной карточкой; сбор
из карточки товара ограничен этим товаром. Seller API используется для каталога.

## Установка и первый запуск

В `https://one.customcraft-mes.ru/parity/integrations` нажмите «Скачать расширение».
Распакуйте архив в постоянную папку. В `chrome://extensions` или `edge://extensions`
включите режим разработчика, нажмите «Загрузить распакованное расширение» и выберите
папку с `manifest.json`. Установка в личный браузер выполняется пользователем;
расширение не устанавливается скрыто и не публикуется автоматически в магазине.

В этом же профиле войдите в BellenneOne и обновите интеграции.
Расширение использует текущие условия вашего браузера без проверки входа и региона. Должно появиться «Расширение подключено».
Проверьте WB и Ozon и сверьте показанные значения; затем запускайте весь каталог.
Оставьте Parity открытой, компьютер и браузер должны работать. Временная задержка
фоновых вкладок увеличивает длительность сбора. Веб-расписание запускает только
серверный сборщик; автоматический запуск расширения по расписанию не реализован.

Для другого адреса BellenneOne пересоберите архив (внешний адрес должен быть HTTPS):

```powershell
python apps/parity/extension/build.py --origin https://bellenne.example
```

Docker автоматически собирает пакет для `https://one.customcraft-mes.ru` и
localhost/127.0.0.1:17863. Основной адрес — HTTPS-домен. ZIP доступен в защищённом endpoint
`/parity/browser-extension`, исходники — `apps/parity/extension/`.

## Очередь и восстановление

Серверные `BrowserRun` / `BrowserTask` хранят назначение, порядок, токен карточки,
статус и текущую позицию. `ActiveJob` запрещает параллельные задания владельца.
Обычный worker исключает browser jobs из claim и таймаута server lease. Паузу
можно оставить на длительное время; она не превращается в отказ worker.

Расширение хранит в `chrome.storage.local` случайный ID контекста браузера,
ID задания/вкладок и один непереданный результат. Состояние не зависит от жизни
MV3 service worker; обработчики событий, вкладка Parity и alarm восстанавливают
работу. Короткие таймеры улучшают темп, но курсор и результат сохраняются до них.
После перезапуска откройте страницу задания в том же профиле.

Принятие результата идемпотентно и атомарно: токен/задание/профиль, текущая карточка,
структура DOM-наблюдения, артикул, валюта и Wallet/Card проверяются на сервере.
Проверка города в браузерном сборе отключена; серверная гостевая диагностика
сохраняет отдельный настроенный регион.
Текущее наблюдение старше двух HTTP-таймаутов (по умолчанию 60 секунд) перечитывается.
Повтор ответа после потери связи не создаёт дубль snapshot. Сравнения остаются stale
до завершения/остановки очереди; весь каталог не пересчитывается на каждую карточку.

Любая ошибка карточки автоматически фиксируется как skipped с причиной в журнале,
без нового снимка цены; очередь переходит к следующему товару. Это включает
«Нет в наличии», blocked, identity, layout, benefit_missing, unavailable,
внутреннюю ошибку вкладки и navigation после ограниченных повторов.
Ручного «Продолжить» после ошибки не требуется. Пауза и остановка выполняются
только по команде пользователя. CAPTCHA не решается — карточка пропускается.
При временной потере связи с Parity непереданный результат сохраняется и
подтверждение повторяется автоматически после восстановления соединения.

### Окно расширения (1.1)

Нажатие на значок показывает реальный счётчик обработанных карточек, число
сохранённых цен и пропусков, текущий артикул/площадку, этап и время последней цены.
Прогресс хранится в extension storage и остаётся доступен после закрытия окна и
завершения задания. «Пауза», «Продолжить», «Пропустить карточку» работают через
авторизованную вкладку Parity с проверками владельца, CSRF и профиля. Остановить
весь сбор можно на странице задания. Кнопки открытия ведут к заданию и рабочей
карточке. При потере связи очередь сохраняется, а окно предлагает открыть Parity.

Ответ content script ограничен существующим сетевым таймаутом 10 секунд:
отсутствующий ответ не удерживает очередь обещаний навсегда. Чтение DOM может
начаться до окончания загрузки картинок/аналитики, если content script уже готов.
Отсутствие ответа читателя за два таймаута карточки переводит сбор в ожидание
действия. Проверки идентификатора, региона и способа оплаты остаются обязательными.

Обновление установленной версии: замените содержимое той же распакованной папки,
нажмите кнопку перезагрузки BellenneParity в `chrome://extensions` или
`edge://extensions`, затем обновите вкладку задания. Не удаляйте расширение:
переустановка может изменить контекст браузера. Позиция очереди остаётся на сервере.

## Контекст цены и безопасность

Общий DOM-reader `app/static/storefront-extract.js` используется и сервером, и
расширением. Расширение ждёт два совпадающих наблюдения, игнорирует рассрочку и
рекомендации. Проверяется SKU карточки, регион не блокирует сбор; для Ozon используется
покупательский SKU. Обычная цена не подставляется вместо карты/кошелька.

Снимок содержит `collector=extension`, `session=browser_profile`, условия цены и
версию контекста. Вход/выход из аккаунта не определяется автоматически: аккаунт
и адрес нужно поддерживать неизменными во время задания. При смене аккаунта
остановите сбор и нажмите «Сменить контекст браузера» до нового запуска. Изменение
ID контекста или переход между сервером и браузером увеличивает версию условий;
история разных версий не склеивается, старые цены не сравниваются с новыми.

Расширение не получает Seller API secrets и не читает cookies/пароли сайтов.
API использует действующую Bellenne-сессию вкладки, server-side owner checks и CSRF;
нового анонимного API, bearer credential или открытого CORS нет. Мост принимает
только claim, receipt и control, без произвольного URL. Содержимое страницы, имена
аккаунтов, cookies и заголовки авторизации серверу не передаются. Права extension
ограничены storage/alarms, WB, Ozon и адресами Bellenne из сборки; `all_urls`,
cookies, webRequest, downloads и доступ к файлам не запрашиваются. Контент-скрипты
работают в isolated world, сообщения принимаются только от этого extension,
основного frame и назначенной рабочей вкладки. Снимки JPEG в extension mode не
создаются: подтверждение — структурированное наблюдение видимого DOM.

## Проверки и границы приёмки

Тесты очереди покрывают owner/CSRF/profile/token, конкурентное принятие,
блокировку/регион/карту, паузу до подключения, skip/stop, разделение контекстов,
исключение из worker и сохранность истории. Тесты `test_extension.py` загружают
настоящий MV3 пакет в persistent Chromium и проверяют запуск из UI, динамические
WB/Ozon fixtures, полное завершение, перезапуск профиля и потерю ответа после commit.
Fixtures не используют реальные аккаунты; успех тестов не гарантирует отсутствие
ограничений на реальных маркетплейсах. Проверка в личном Chrome/Edge на карточках
WB 701955470 и Ozon 3267204518 требуется после установки расширения пользователем.


### Исправление 1.1.1: старое задание после обновления профиля

Проверка terminal state выполняется до проверки browser client ID: принадлежащее
владельцу завершённое/остановленное задание возвращает finished без task, даже
если локальный контекст изменился. Это позволяет удалить устаревший курсор
расширения и перейти к новому заданию. Профиль и контекст старого задания, снимки
и очередь не изменяются. Живое задание по-прежнему не принимает другой профиль.

Это серверное исправление работает и с уже установленной версией 1.1.0. Popup
1.1.1 отдельно показывает конфликт профиля и необходимость входа, не предлагает
бесконечное обновление при конфликте и не выводит выдуманные 0/0 или #undefined.
Регрессионные тесты воспроизводят старое terminal задание с другим client ID,
переход нового MV3 профиля к следующему заданию и настоящий конфликт живой очереди.


### Автоматическое восстановление 1.2

Только ошибка navigation получает ограниченные автоматические повторы той же
карточки. Максимум попыток, включая первую, берётся из PARITY_RETRY_ATTEMPTS
(текущий default 3). Вторая попытка заново загружает карточку, третья и последующие
закрывают только рабочую вкладку расширения и создают новую в том же профиле.
Пауза перед повтором равна page_interval_seconds × номер попытки; при стандартном
интервале 2 секунды это 4 и 6 секунд. Ошибка navigation автоматически не пропускает карточку. После
исчерпания бюджета карточка автоматически пропускается, очередь идёт дальше.

Попытка, срок ожидания и план замены вкладки сохраняются в chrome.storage.local:
пауза/перезапуск не обнуляют бюджет. Успех следующей карточки начинает новый бюджет.
После исчерпания попыток товар получает пропуск navigation без ручного действия. Старый ID закрытой вкладки восстанавливается без потери
курсора и без бесконечного сообщения «No tab with id».

Окно показывает «Автоматический повтор · попытка N из M». Вкладка не получает
фокус на промежуточных попытках. Обнаруженные blocked/layout/
benefit_missing не повторяются автоматически: карточка пропускается. Несовпадение идентификатора (`identity`)
автоматически пропускает карточку без повторного открытия. Потеря связи с Parity не
меняет карточку и не выбрасывает ожидающее подтверждение результата.

Помимо обычного читателя с таймером, сообщения SAMPLE берут немедленный снимок
видимых элементов страницы. Два одинаковых валидных снимка с интервалом не менее
секунды могут завершить чтение, даже когда таймер фонового документа задержан.
Проверки цены на сервере и идемпотентное принятие результата остаются прежними.

Тесты настоящего MV3: зависания первых двух загрузок/успех третьей без дубля,
исчерпание бюджета без снимка, сохранение попытки после pause/restart, отсутствие
автоповтора challenge, чтение через SAMPLE при зависшем таймере документа.


### Автоматический пропуск неверного SKU

Сервер автоматически отмечает карточку как skipped/identity, если расширение
сообщило о несовпадении SKU или проверка наблюдения на сервере выявила его.
Отсутствующий/невалидный покупательский SKU в каталоге также пропускается до
открытия страницы. Снимок чужой цены не создаётся; предыдущая история сохраняется,
товар получает ошибку identity и исключается из актуального сравнения.

Пропуск увеличивает done и skipped, сохраняет CollectionAttempt и событие
collection_error с automatic=true. Повторная доставка результата, включая потерю
ответа после commit, не увеличивает счётчик и не пропускает следующий товар.
Смешанный результат заканчивается partial, только пропуски — failed.

Для уже остановившегося задания attention/identity следующий claim связанного
профиля автоматически пропускает текущую карточку и продолжает очередь.
Пауза пользователя остаётся паузой; другой профиль не может продолжить задание.
Обновление расширения не требуется: accepted=true подтверждает обработку карточки,
а saved/skipped отдельно показывают сохранённые цены и пропуски.

Проверки: backend (ошибка расширения и несовпадение DOM, неверный SKU каталога,
повторные/одновременные результаты, последняя карточка, существующая остановка,
профиль и пауза); настоящий MV3 (Ozon с неверным SKU, потеря ответа после пропуска,
успешный WB и итог 2/2, одна цена, один пропуск без ручного продолжения).


### Версия 1.2.1: сбор без остановки на входе и регионе

Удалена остановка setup с требованием входа в WB/Ozon и выбора Москвы.
Она срабатывала по адресу страницы, без проверки реального входа в аккаунт.
Регион больше не проверяется ни в расширении, ни при принятии его наблюдений.
Снимок содержит только наблюдаемый город (либо null), region_checked=false;
Москва не подставляется вместо неизвестного региона.

Переходы внутри WB/Ozon, включая адреса без www, читаются как обычные страницы.
Чужой сайт не читается: такая карточка отмечается unavailable и пропускается.
Неподтверждённый SKU также пропускается; цена кошелька/карты остаётся обязательной.
Старые setup/region от установленного расширения принимаются как пропуск, а уже
стоящая attention/setup или attention/region продолжает очередь следующим claim
связанного профиля. Пауза пользователя и изоляция профилей остаются в силе.

Для чтения цены без локальной проверки Москвы замените файлы распакованного
расширения версией 1.2.1 и перезагрузите его в chrome://extensions. Удалять и
устанавливать заново не нужно. Серверное продолжение legacy setup/region работает
сразу после обновления сервера, включая ещё установленную версию 1.2.0.


### Версия 1.2.2: все ошибки карточки — пропуск

Сервер больше не создаёт attention из receipt: любой код ошибки отмечает только
текущую карточку skipped, сохраняет CollectionAttempt/collection_error с
automatic=true, затем выдаёт следующую. Прежние остановки attention, включая
неизвестный старый код, восстанавливаются на следующем claim того же профиля.
Paused остаётся ручной паузой. Владение, CSRF, профиль, токен и порядок карточек
проверяются; дубли receipt не пропускают следующий товар.

Читатель распознаёт видимое «Нет в наличии»/«Товар закончился» без блока цены и
передаёт unavailable. Текст в рекомендациях не заменяет цену основной карточки.
Два совпавших наблюдения blocked/unavailable завершают чтение быстрее таймаута.
Необработанная локальная ошибка назначенной вкладки передаётся как internal и
также пропускается. Ошибки связи с Parity сохраняют непереданный результат;
восстановление соединения не требует выдуманной цены или нового задания.

Общий автопропуск действует со старыми версиями расширения сразу после обновления
сервера. Быстрое распознавание отсутствия товара и обработка локальных сбоев
поставляются в ZIP/распакованной папке 1.2.2; установленный браузер подхватывает
новый код после перезагрузки расширения в прежней папке.

Проверки: полный набор 114 тестов (95 backend/витрина/очередь, 19 настоящих MV3).
Смешанная очередь из пяти карточек: blocked Ozon → цена WB → WB «Нет в наличии» →
layout WB → цена WB; итог done=5, saved=2, skipped=3, без ручного продолжения.
Проверены все серверные коды ошибок, старые остановки, дубли/одновременные receipt,
исчерпание navigation, сохранение бюджета pause/restart, локальный сбой вкладки,
потеря связи после commit, чтение через SAMPLE и сохранение прежней истории.

### Версия 1.2.3: производственный адрес

Стандартный ZIP и Docker-сборка поддерживают `https://one.customcraft-mes.ru/parity`,
включая корневой адрес без завершающего `/`. Остальные пути этого хоста и чужие
домены не становятся мостом Parity. Сохраняется поддержка локального gateway.
При новом сборе расширение фиксирует origin установки: кнопка открытия задания
и восстановление связи используют этот адрес. Активное задание и непереданные
результаты не перебрасываются между установками с одинаковым номером задания.
Для обновления замените файлы в прежней папке распакованного расширения, нажмите
«Обновить» на странице расширений и обновите страницу Parity.
