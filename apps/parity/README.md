# BellenneParity

Контроль цен WB/Ozon в BellenneOne. UI: `/parity/`; настройки:
`/parity/integrations`. Требования: [TZ_PARITY](../../docs/TZ_PARITY.md),
[продукт](../../docs/products/PARITY.md), [API mapping](../../docs/PARITY_API.md).

## Запуск

Из корня BellenneOne:

```powershell
docker compose up -d --build parity parity-worker shell gateway
```

Не запускайте отдельный внешний uvicorn с доверенными auth-заголовками.
Gateway перезаписывает заголовки после проверки платформенной сессии; сервис
не публикует отдельный порт. Каждому аккаунту принадлежат собственные подключения,
товары, связи, история и журнал. Доступ по ID чужого аккаунта возвращает 404.

1. Откройте «Интеграции», скачайте расширение и загрузите распакованную папку в Chrome/Edge. Условия сбора: Москва, WB Кошелёк / Ozon Карта, текущий профиль браузера. Войдите в нужные аккаунты и обновите страницу Parity. Настройте паузу между карточками.
2. Если каталог ещё не импортирован, сохраните WB token / Ozon Client ID + API Key и нажмите «Импортировать каталог». Ключи нужны только для артикулов и SKU.
3. Нажмите «Проверить WB» / «Проверить Ozon» или «Собрать эту карточку» внутри товара. Проверка идёт через очередь и сохраняет цену только при подтверждённом регионе и способе оплаты.
4. После успешной проверки можно собрать весь каталог одной кнопкой. Оставьте вкладку Parity открытой. Пауза, продолжение, пропуск карточки и остановка находятся на странице задания. Расписание в UI относится только к серверному гостевому сборщику.
5. Старые цены доступны в карточке в «История Seller API» и не участвуют в текущем сравнении.

**Приёмка:** оба сайта ограничили Chromium из Docker, поэтому основной запуск переведён на расширение. Оно проверено в настоящем Chromium на динамических fixtures, включая перезапуск и потерю ответа сервера. Реальные карточки в личном Chrome/Edge нужно проверить после установки расширения пользователем. Подробности: [расширение](../../docs/PARITY_EXTENSION.md), [серверный сбор](../../docs/PARITY_STOREFRONT.md).

Секреты не нужно передавать в `.env`. `PARITY_ENCRYPTION_KEY` задаёт ключ Fernet
инфраструктуры. Если он не задан, защищённый ключ автоматически создаётся в
`parity_data/credentials.key`. API и worker используют один volume. Резервируйте
volume целиком; без ключа сохранённые credentials нельзя расшифровать.

## Архитектура

- `domain.py`: нормализованные DTO и Decimal арифметика;
- `adapters.py`: только read-методы официальных API, пагинация, rate limits;
- `models.py`, `db.py`: отдельная SQLite БД, базовая версионированная миграция;
- `service.py`: staging, атомарная публикация каталога площадки, snapshots,
  mappings, сравнения, долговечная очередь и расписание;
- `storefront.py`: Chromium, ожидание динамического DOM, проверка артикула / Москвы / кошелька или карты;
- `collection.py`: импорт каталога без API-цен и транзакции браузерного сбора по карточкам;
- `worker.py`: выполнение задания вне HTTP;
- `browser.py`, `extension/`: долговечная очередь браузера, MV3, same-origin bridge и сборка ZIP с общим DOM-reader;
- `queries.py`: серверный поиск, фильтры, пагинация, ограничение периода истории;
- `main.py`: auth/owner isolation, CSRF, формы и безопасные ответы;
- `templates`, `static`: общий визуальный язык Bellenne.

ActiveJob уникален для владельца: повторный клик возвращает текущее задание.
Worker claim атомарен. Heartbeat обновляется на вызовах API и между пакетами;
задания с истёкшим lease завершаются interrupted, старый worker не может
опубликовать результат завершённого задания. Первоначальные настройки:
HTTP timeout 30 с, 3 попытки, worker idle 1 с — как у существующих интеграций;
lease 300 с оставляет запас для запросов и разрешённого bounded backoff.
Они доступны через `.env.example`; расписание и stale policy — через UI.

Каждое успешное браузерное наблюдение сохраняет снимок цен, условия и время. Источник и версия условий отделяют историю от старого API. Ошибка не заменяет предыдущую цену, но исключает её из актуального сравнения. При блокировке следующие карточки площадки пропускаются; другие площадки обрабатываются отдельно. Снимок основного блока цены доступен владельцу, если screenshot удалось сохранить.

Ручная отвязка сохраняет singleton mappings с типом manual; автоматика не
восстанавливает их. Автоматические связи перепроверяются при изменении артикула
или появлении дублей. История остаётся привязана к marketplace product ID.

График выбирает 7/30/90 дней или весь период; null делает разрыв. Таблица истории
пагинирована. При более 5000 точках график просит сузить период, таблица остаётся
доступной. Неограниченная многолетняя история не отправляется в браузер.

## Проверки

```powershell
docker build --target browser-test -t bellenneone-parity-browser-test -f apps/parity/Dockerfile .
docker run --rm bellenneone-parity-browser-test
```

Из `apps/parity`, если зависимости установлены:

```powershell
python -m unittest discover -s tests -v
```

`tests/preview_server.py` — отдельный синтетический preview для визуальной QA.
Он не включён в runtime image и не имеет production-авторизации или live API.

## Проверки и ограничения

68 тестов прошли в Python 3.12 / Chromium: регрессии старой истории, миграция, динамический DOM, строгие проверки условий, блокировки, частичная загрузка, точные цены, доступ владельца, CSRF и шифрование. Реальный live smoke для FFO-039_300x270 подтвердил блокировку обеих площадок из Docker и отсутствие неподтверждённых снимков. Требуется отдельно проверить доступность выбранного браузера / окружения и ежедневный запуск до активации расписания. Работа не меняет цены площадок.
